# قواعد عدم المساس بالتصميم — Guardrails

> **هذه القواعد ملزمة.** أي تعديل يخالفها يُرفض ويُعاد.
>
> **السياق:** v0 أفسد التصميم في محاولة سابقة. استُعيد القالب الأصلي (13 قسمًا)،
> **والمطلوب الآن إكمال العمل دون المساس بهذا التصميم أو مظهره أو صوره.**

---

## 1. الملفات المقدّسة (لا تُلمس دون موافقة صريحة)

| المسار | السبب |
|---|---|
| `app/layout.tsx` | نقطة الجذر — أي تغيير يمسّ كل الصفحات |
| `app/page.tsx` | **تركيب الأقسام الـ13** — ترتيبها وتكوينها ثابت |
| `app/globals.css` | الرموز اللونية والخطوط والحلقة الأساسية |
| `styles/` | طبقة الأنماط |
| `components/landing/*` | **كل قسم** — البنية والتصميم |
| `components/ui/*` | مجموعة shadcn/ui — لا تُعدَّل، تُستخدم فقط |

**القاعدة:** في المراحل 1 و5 و6 — **صفر لمس** لهذه الملفات.

---

## 2. قواعد التغيير البصري

1. **لا إعادة تصميم.** يُنقل القسم كما هو. النص العربي يُضاف داخل البنية القائمة.
2. **لا تغيير ألوان أو خطوط أو مسافات أو ظلال** في المراحل 1–3 إلا بموافقة صريحة.
3. **لا حذف أقسام.** العناصر غير الحقيقية تُعطَّل **بالعرض فقط** خلف علم، ولا تُحذف.
4. **الخصائص الاتجاهية:** التحويل إلى خصائص منطقية مسموح **فقط** إذا حافظ على
   البصمة البصرية نفسها في `LTR`. أي انزياح = رفض.
5. **لا مكتبات UI جديدة** تفرض نمطها البصري.

## 4. خطة التراجع (Rollback)

| الحالة | الإجراء |
|---|---|
| أفسدنا قسمًا | `git checkout main -- components/landing/<file>` |
| أفسدنا التركيب | `git checkout main -- app/page.tsx` |
| أفسدنا الأنماط | `git checkout main -- app/globals.css styles/` |
| أفسدنا كل شيء | `git checkout main` ثم فرع جديد من `main` |

**ملاحظة:** فرع `main` هو **مرجع التصميم الصحيح**. أي انحراف عنه في ملف بصري =
استرجاع الملف من `main` فورًا.

---

## 5. قواعد الأسرار (غير قابلة للتفاوض)

1. **لا توكنات ولا مفاتيح في المستودع** — لا في ملف، ولا في `.env.example`،
   ولا في التزام، ولا في تعليق، ولا في وثيقة.
2. توكن Vercel محفوظ **خارج المستودع** في `~/.config/agentnexos/vercel.env`
   بصلاحيات `600`.
3. مفاتيح Groq تبقى **في Vercel فقط** — تُقرأ من بيئة التشغيل، ولا تُنسخ محليًا،
   ولا تُطبع في سجلات.
4. `.env.example` يحتوي **أسماء وقيمًا وهمية** فقط.
5. أي ملف يحتوي سرًّا يجب أن يكون في `.gitignore`.

**سبب القاعدة:** التوكن المدفوع للـGit = تسريب دائم. حتى حذف الملف لاحقًا لا يمحو
التاريخ. وطبيعة مفاتيح المزوّدين سرية بلا استثناء.

---

## 6. قواعد الأمانة (مطابقة الادّعاء للتنفيذ)

1. كل ميزة على الموقع موسومة **«متاح الآن»** أو **«خارطة الطريق»**.
2. **لا اختراع**: عملاء، شهادات، شعارات، أرقام، تكاملات، شهادات امتثال.
3. الكونسول يوصف كـ**عرض حتمي**، لا كوكلاء نماذج لغوية مستقلين.
4. **لا ادّعاء OCR** ولا تنفيذ كود مرفوع ولا «صندوق رملي أمني».
5. الأرقام في المقالات: مسجَّلة بمصدرها، أو محذوفة.

---

## 7. سير العمل في Git

1. **لا دفع مباشر إلى `main`.** كل مرحلة على فرعها: `phase-N-<name>`.
2. **شرط الدفع:** `pnpm build` ينجح.
3. **التزام واحد لكل مهمة متماسكة** برسالة عربية واضحة.
4. **الالتزامات الصغيرة** أسهل في المراجعة والتراجع من الالتزامات الضخمة.
