# تجهيز بيئة Agentnexos السحابية — 1 أكتوبر 2026

## النطاق والنتيجة

عُثر على المستودع في `/workspace/agentnexos` داخل البيئة السحابية المتصلة بالمحادثة. أداة الحالة تعرض البيئة المتصلة فقط؛ لم تعرض قائمة البيئات الأخرى أو إعدادًا باسم المشروع. الحالة المرصودة `running` و`connected` وحديثة، وسياسة HTTP غير مقيدة ومطبقة عبر proxy البيئة. لا توجد أسرار أو متغيرات تشغيل أو هويات outbound مربوطة بهذه البيئة حسب أداة الحالة.

هذه دفعة تجهيز وتوثيق، لا تغيير لواجهة التطبيق أو ألوانه أو صوره، ولا تفعيل لإجراءات مؤسسية. المرجع البرمجي قبل التجهيز: `e8f1fed64be4f5bb66befc302f3c091265fb152e` على `main`، مطابق للمستودع العام وقت الفحص.

## الاعتمادات المثبتة

تم تشغيل `pnpm install --frozen-lockfile` دون تعديل manifest أو lockfile، ثم تثبيت Chromium الخاص بإصدار Playwright المقفل.

| المكوّن | الإصدار الموجود |
|---|---|
| Node | 24.19.0 |
| pnpm | 11.19.0 |
| Next.js | 16.3.7 |
| AI SDK / ai | 7.0.118 |
| @ai-sdk/react | 4.0.125 |

AI SDK وMastra موجودان بالفعل في التطبيق. Eve غير مثبت وغير مستخدم؛ تثبيت الاعتمادات الحالية لا يضيف إطار تشغيل آخر ولا يثبت durable execution. اختيار إطار للحفظ والاستئناف يأتي ضمن مرحلة التنفيذ الدائم بعد دراسة متطلبات المشروع.

## إعادة التجهيز والتشغيل

من مجلد المستودع، مع الحفاظ على إعدادات proxy وشهادات TLS الموروثة من البيئة:

```bash
cd /workspace/agentnexos
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
pnpm typecheck
pnpm test:agentnexos
pnpm i18n:check
pnpm dev --hostname 0.0.0.0
```

التطوير على المنفذ 3000، والمساران `/ar` و`/en`. استخدم رابط معاينة البيئة إذا كانت واجهة البيئة توفره؛ لا يوجد رابط معاينة سحابي جديد مثبت في هذا التقرير.

لبناء وتشغيل نسخة محلية للإصدار:

```bash
pnpm build --webpack
pnpm start --hostname 0.0.0.0
```

خيار webpack مدعوم في Next المثبت، واستُخدم للبناء المحلي بسبب تجربة تعثر جلب الخطوط عبر proxy مع Turbopack في الدورة السابقة. لا تُعطل TLS أو تغير الخطوط لتجاوز المشكلة. يبقى أمر البناء المعتاد `pnpm build` في المشروع؛ نجاح البناء المحلي بهذا الخيار ليس دليلًا على نشر جديد في Vercel.

للفحص الشامل، شغّل خادم النسخة المبنية ثم، في طرفية أخرى:

```bash
SITE_URL=http://localhost:3000 pnpm verify:site
```

راجع [دليل التحقق من الإصدار](RELEASE-VERIFICATION.md) لأسماء المتغيرات وحدود الفحص والأدلة. لا تشغّل الاختبارات التاريخية التي تحتاج قاعدة أو أدوات كتابة على الإنتاج لمجرد وجود script لها.

## الأسرار وحدود التشغيل المحلي

لا يوجد `.env.local` عند الفحص، ولم تُنسخ أسرار Vercel أو المفاتيح الواردة في المحادثة إلى البيئة. تبقى مفاتيح Groq في Vercel وفق حمايات المشروع. صفحات المنتج والموجز المحلي والفحوص غير المدفوعة يمكن تجهيزها دون هذه الأسرار؛ نجاحها لا يعني أن التجربة الحية تعمل محليًا.

ملف `.env.example` يشرح أسماء الإعدادات بقيم وهمية. لا تضع مفتاحًا في Git أو التوثيق. لا تستخدم `vercel env pull` لسحب أسرار الإنتاج إلى هذا workspace. اتصال أدوات Vercel أو Supabase لا يعني أن عملية Next المحلية ورثت مفاتيح تلك الخدمات.

التجربة المنشورة مستقلة عن حالة هذه البيئة المحلية. المرجع الأحدث للجاهزية وسياسة الاستخدام هو [FIX-BUDGET](phases/FIX-BUDGET-2026-10-01.md): 1000 طلب لكل اتصال و10000 إجمالًا خلال نافذة 24 ساعة، منفصلة عن حدود حساب Groq. هذه هوية اتصال وليست هوية مستخدم مسجل؛ الاتصالات خلف عنوان خروج مشترك تتشارك السقف. لم تغيّر دفعة التجهيز هذه الحدود أو قاعدة البيانات.
