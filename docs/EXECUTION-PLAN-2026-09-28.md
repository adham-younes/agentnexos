# خطة تنفيذ ترقية Agentnexos

**المرجع البصري:** القالب الحالي وصوره وتكوينه الهندسي كما هو منشور على الإنتاج بعد الالتزام `308c95a`.

## 1. تعريف المنتج

Agentnexos منصة لبناء وتشغيل أنظمة وكيلة مخصصة للمؤسسات والشركات في مصر والخليج والشرق الأوسط. تربط المعرفة المؤسسية بالأدوات والأنظمة الحالية، وتحوّل العمليات المتكررة إلى سير عمل آلي مضبوط، مع صلاحيات محددة، موافقات بشرية عند الأفعال الحساسة، وسجل قابل للفحص.

لا تُقدَّم المنصة كروبوت محادثة عام، ولا كمنصة لمعالجة المستندات فقط. معالجة المستندات قد تكون أداة داخل عملية، وليست هوية المنتج.

## 2. القواعد البصرية الملزمة

1. القالب الأصلي هو أساس جميع المراحل القادمة.
2. لا يُستبدل التصميم العام، ولا الصور، ولا ترتيب الأقسام دفعة واحدة.
3. تعديل المحتوى يتم داخل مكونات القالب الحالية وبنفس نسب الصور والمسافات والشبكة.
4. أي تعديل بصري يُنفذ موضعيًا ويُراجع على العربية والإنجليزية عند 390 و768 و1440 بكسل.
5. لا دفع للإنتاج قبل مقارنة صور قبل وبعد واعتماد عدم وجود قص أو تمدد أو اختلال RTL/LTR.
6. إذا أخفق تعديل في الحفاظ على القالب، يُلغى التعديل قبل الانتقال إلى عمل آخر.

## 3. نظام المحتوى الجديد

المحتوى يجب أن يشرح قيمة تشغيلية حقيقية، وفق التسلسل التالي:

- المشكلة التشغيلية داخل المؤسسة.
- البيانات والأنظمة التي تمثل مصدر الحقيقة.
- دور الوكيل وحدود سلطته.
- الأدوات التي يقرأ أو يكتب من خلالها.
- نقاط الموافقة والتصعيد البشري.
- النتيجة القابلة للقياس ودليل نجاحها.

يُمنع نشر أرقام أداء أو عملاء أو شهادات أو تكاملات أو امتثال أو أسعار ما لم تكن موجودة وقابلة للتحقق. الميزات المستقبلية تُوسم بوضوح بأنها قيد التطوير.

## 4. البحث المرجعي للمحتوى

يُبنى المحتوى على تحليل تحريري لعشر منصات عربية أو موجهة لسوق MENA، مع الاعتماد على المواقع الرسمية. القائمة المرجعية الأولية:

1. Mozn
2. Arabic.AI
3. SandRock
4. Gaia
5. tkana
6. Oryx Data OCT.AI
7. Alpha Pro MENA
8. Elama
9. Menatic
10. Conneqt

هذا اختيار تحريري بحسب الصلة بالوكلاء المؤسسيين والعربية والسيادة والأتمتة، وليس تصنيفًا عالميًا مطلقًا. لا يُنسخ نص منافس؛ تُستخلص أنماط العرض وحالات الاستخدام والفجوات فقط.

## 5. المراحل

### المرحلة 1 المحتوى والهوية داخل القالب

- الحفاظ الكامل على القالب وصوره.
- إعادة كتابة Hero والأقسام الحالية لتعريف منصة أنظمة وكيلة للمؤسسات.
- إزالة أو تعطيل الادعاءات غير المدعومة دون ترك فراغات بصرية.
- توحيد المعنى بين العربية والإنجليزية.
- إصلاح الروابط والأزرار داخل الأقسام الموجودة.
- تحسين الخط العربي داخل نظام الخطوط الحالي فقط.

**بوابة الخروج:** تطابق هيكلي مع القالب، مراجعة بصرية كاملة، نجاح build وi18n، ثم Preview وموافقة قبل الإنتاج.

### المرحلة 2 الصفحات وحالات الاستخدام

- إضافة صفحات المنصة والحلول والقطاعات والأمان والمصادر القانونية بصورة مشتقة من القالب.
- حالات استخدام: المبيعات، المشتريات والعقود، خدمة العملاء، العمليات الداخلية، اللوجستيات والخدمات المهنية.
- تنظيم التنقل والروابط وSEO باللغتين.

**بوابة الخروج:** كل صفحة تعمل بالعربية والإنجليزية، ولا رابط ميت، وفحص بصري لكل المقاسات، ثم نشر إنتاجي موثق.

### المرحلة 3 الوكيل التجريبي Agentnexos

- واجهة تواصل منسجمة مع القالب، وليست إعادة تصميم للموقع.
- Vercel AI SDK كأساس لواجهة التدفق والأدوات المصنفة.
- يبدأ الوكيل بتحليل عملية المؤسسة وإنتاج عقد أتمتة: الهدف، المدخلات، الأنظمة، الحالات، المخاطر، الموافقات، ومؤشرات النجاح.
- لا تنفيذ خارجي في البداية؛ تُضاف الأدوات التنفيذية بعد اختبارات وصلاحيات وموافقة.
- يُقيّم إدخال Mastra عند وجود حاجة مثبتة للتنفيذ الدائم والتنسيق، وليس لمجرد إضافة إطار ثانٍ.

**بوابة الخروج:** محادثة إنتاجية حقيقية، أداة واحدة على الأقل تعمل، أخطاء واضحة عند غياب الاعتماد، وتقييمات وسجل إصدار.

### المرحلة 4 Supabase والاستمرارية

- مشروع Supabase مستقل لـAgentnexos؛ لا يُعاد استخدام مشروع غير متعلق.
- جداول المؤسسات والعضويات وتعريفات العمليات والتشغيلات والأحداث والموافقات وتنفيذ الأدوات والمخرجات وسجل التدقيق.
- RLS على كل جدول مكشوف وفصل صارم بين المؤسسات.
- استخدام publishable key في العميل، وعدم كشف secret أو service role.
- تطبيق الهجرات أولًا على بيئة تطوير أو فرع قاعدة بيانات، ثم الفحص الأمني قبل الإنتاج.

**بوابة الخروج:** اختبار فصل مؤسستين، استمرار تشغيل بين جلستين، فحص مستشاري الأمان والأداء، ثم ترحيل إنتاجي موثق.

### المرحلة 5 الأدوات والتنفيذ الواقعي

- البحث اللحظي بمصادر وروابط وحدود زمنية.
- موصلات ضيقة الصلاحية للبريد وCRM/ERP والتخزين وفق الحاجة الفعلية.
- تنفيذ الكود داخل Sandbox معزول وحدود موارد وشبكة.
- idempotency ومنع التكرار، retries محدودة، وتسوية قبل إعادة الكتابة في الأنظمة الخارجية.
- موافقة بشرية مرتبطة بمعلمات الفعل المحددة وتنتهي صلاحيتها.

**بوابة الخروج:** رحلة واحدة كاملة من طلب إلى أداة إلى موافقة إلى تحقق من النظام النهائي، ثم نشر إنتاجي.

### المرحلة 6 الذاكرة والتكاملات والتشغيل المؤسسي

- فصل working state عن الذاكرة المستمرة والمعرفة المؤسسية.
- استرجاع مختلط مع فلترة صلاحيات قبل وصول السياق إلى النموذج.
- قياس التكلفة والسرعة ودقة استدعاء الأدوات والنتيجة التجارية.
- مراقبة وسجلات ونسخ احتياطية واستجابة للحوادث وخطة تراجع.

**بوابة الخروج:** اختبارات تحميل وأمان واسترجاع ونسخ احتياطي، توثيق التشغيل، ثم نشر إنتاجي.

## 6. خط النشر لكل مرحلة

1. فرع مرحلة مستقل.
2. تنفيذ موضعي محدود.
3. lint وtypecheck وi18n وbuild واختبارات الوحدة.
4. Vercel Preview.
5. فحص بصري آلي ويدوي للعربية والإنجليزية.
6. اختبار رحلة المستخدم المقصودة، وليس الصفحة الرئيسية فقط.
7. دمج إلى `main` بعد نجاح البوابات.
8. انتظار حالة Vercel `READY`.
9. إثبات Git SHA من الإنتاج، وفحص الصحة والرحلة الكاملة.
10. إضافة سجل إصدار داخل `docs/releases/` مع رابط النشر والنتائج وخطة التراجع.
