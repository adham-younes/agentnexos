## 2. ترتيب المراحل ومعايير القبول (Phases & Acceptance Criteria)

### المرحلة 3: التوثيق والهوية وغلاف مساحة الوكيل وأدوات الجودة وCI
- **النطاق:**
  1. تثبيت وضبط ESLint وإصلاح فحص `pnpm lint`.
  2. إنشاء سير عمل GitHub Actions CI (`.github/workflows/ci.yml`) يشمل `typecheck` و `i18n:check` و `build` و `lint`.
  3. تصميم ونشر أيقونة Agentnexos أصلية ومقروءة بالأحجام الصغيرة مع الاحتفاظ بالأصول السابقة لإمكانية التراجع.
  4. بناء واجهة مساحة الوكيل (`/[locale]/agentnexos`) كغلاف آمن احترافي ثنائي اللغة يعرض حالة النظام والمحاكاة المنضبطة للمسار الحتمي، وتوضيح حالة عدم توفر الاعتمادات، دون أي بيانات وهمية كاذبة.
- **معايير القبول:** نجاح جميع بوابات الفحص (`typecheck`, `i18n:check`, `build`, `lint`)، فحص بصري على 390 و 768 و 1440 بكسل، نشر preview ثم الدمج إلى main والتحقق من الإنتاج.

### المرحلة 4: Supabase والهوية والحالة الدائمة
- **النطاق:** إعداد migrations للجداول (`organizations`, `profiles`, `memberships`, `agent_threads`, `agent_runs`, `tool_calls`, `approvals`, `audit_events`)، تفعيل RLS واختبار عزل المؤسسات (tenant isolation)، ربط عميل الخادم والعميل العام بأمان.
- **معايير القبول:** جداول كاملة، سياسات RLS مشددة تمنع تسريب البيانات بين المؤسسات، واختبارات تكامل تمر بنجاح.

### المرحلة 5: Runtime متعدد الوكلاء وStreaming وأداة قراءة حقيقية
- **النطاق:** تثبيت Vercel AI SDK وتهيئة نماذج Groq المصرح بها (`qwen/qwen3.8-27b`, `openai/gpt-oss-120b`) مع مسار حتمي fallback، واجهة محادثة تدفقية، وأداة قراءة حقيقية مع إثبات النتيجة.
- **معايير القبول:** streaming حقيقي، معالجة انقطاع الاتصال أو غياب المفتاح بفشل آمن وواضح، استشهاد حقيقي بالدليل.

### المرحلة 6: الأدوات التنفيذية والموافقات والذاكرة
- **النطاق:** أدوات بحث وجلب آمن مع حماية SSRF، بوابة موافقة بشرية معلقة ومحفوظة في قاعدة البيانات (Human-in-the-loop)، ذاكرة تشغيلية ومؤسسية.
- **معايير القبول:** دورة عمل كاملة تقرأ، تطلب موافقة، تنفذ بعد الموافقة، وتسجل دليلاً غير قابل للتكرار غير المقصود (idempotency).

### المرحلة 7: التقييمات والأمان والمراقبة والتعافي
- **النطاق:** حالات تقييم معيارية (eval cases)، حماية ضد prompt injection، حدود استخدام، وتوثيق سجلات التعافي والأخطاء.
- **معايير القبول:** اجتياز نسبة دقة مستهدفة، عدم وجود ثغرات تسريب للمعلومات، سجلات تدقيق مترابطة بـ run_id و step_id.

### المرحلة 8: الصفحات الكاملة والمحتوى ثنائي اللغة وSEO وإمكانية الوصول
- **النطاق:** استكمال صفحات المنصة والحلول والقطاعات والأمان والشروط والخصوصية باللغتين العربية والإنجليزية.
- **معايير القبول:** خلو الموقع من أي روابط معطلة أو ادعاءات غير حقيقية، اجتياز معايير إمكانية الوصول والتوافق مع محركات البحث.

### المرحلة 9: جاهزية Beta المؤسسي
- **النطاق:** التحقق من رحلة مستخدم مؤسسي كاملة من التسجيل إلى تشغيل الوكلاء وإدارة الموافقات.
- **معايير القبول:** رحلة مستقرة ومجربة، غياب أخطاء P0/P1، وإمكانية rollback موثقة.

### المرحلة 10: الإطلاق النهائي والتسليم
- **النطاق:** فحص الإنتاج النهائي الشامل، مراجعة الأداء والموثوقية، وإعداد تقرير التسليم النهائي للمالك.
- **معايير القبول:** مطابقة تامة بين المستودع والإنتاج، وتوثيق كافة المسارات.
