## 2. ترتيب المراحل ومعايير القبول (Phases & Acceptance Criteria)

### المرحلة 4: Supabase والهوية والحالة الدائمة وعزل المؤسسات (منجز ومنشور)
- تم إنجازها ونشرها بنجاح على commit `7cbabea`.

### المرحلة 5: Runtime متعدد الوكلاء وStreaming وأداة قراءة حقيقية (منجز ومختبر)
- **النطاق:** تثبيت Vercel AI SDK وتكوين نماذج Groq المصرح بها (`qwen/qwen3.8-27b`, `openai/gpt-oss-120b`) عبر منسق حتمي مضبوط بالميزانيات والمهلات، واجهة محادثة تدفقية ثنائية اللغة، أداة قراءة حقيقية تستشهد بالدليل، وفشل آمن وشفاف عند غياب المفاتيح.
- **معايير القبول:** streaming حقيقي، معالجة انقطاع الاتصال أو غياب المفتاح بفشل آمن وواضح، استشهاد حقيقي بالدليل، نجاح كافة الفحوصات (تم بنجاح تام).

### المرحلة 6: الأدوات التنفيذية والموافقات والذاكرة (الخطوة التالية)
- **النطاق:** أدوات كتابة وتنفيذ آمنة بمفاتيح idempotency وحماية SSRF، بوابة موافقة بشرية معلقة ومحفوظة في قاعدة البيانات (Human-in-the-loop) مرتبطة بجدول `approvals`، ذاكرة تشغيلية ومؤسسية.
- **معايير القبول:** دورة عمل كاملة تقرأ، تطلب موافقة، تنفذ بعد الموافقة، وتسجل دليلاً غير قابل للتكرار غير المقصود (idempotency).

### المرحلة 7: التقييمات والأمان والمراقبة والتعافي
- **النطاق:** حالات تقييم معيارية (eval cases)، حماية ضد prompt injection، حدود استخدام، وتوثيق سجلات التعافي والأخطاء.
- **معايير القبول:** اجتياز نسبة دقة مستهدفة، عدم وجود ثغرات تسريب للمعلومات، سجلات تدقيق مترابطة بـ run_id و step_id.

### المرحلة 8: الصفحات الكاملة والمحتوى ثنائي اللغة وSEO وإمكانية الوصول
- **النطاق:** استكمال صفحات المنصة والحلول والقطاعات والأمان والشروط والخصوصية باللغتين العربية والإنجليزية.
- **معايير القبول:** خلو الموقع من أي روابط معطلة أو ادعاءات غير حقيقية، اجتياز معايير إمكانية الوصول والتوافق مع محركات البحث.

### المرحلة 9: جاهزية Beta المؤسسي
- **النطاق:** التحقق من رحلة مستخدم مؤسسي كاملة من التسجيل إلى تشغيل الوكلاء وإدارة الموافقات.
- **معايير القبول:** رحلة مستقرة ومجربة، غياب أخطاء P0/P1، وإمكانية rollback موثقة.

### المرحلة 10: الإطلاق النهائي والتسليم
- **النطاق:** فحص الإنتاج النهائي الشامل، مراجعة الأداء والموثوقية، وإعداد تقرير التسليم النهائي للمالك.
- **معايير القبول:** مطابقة تامة بين المستودع والإنتاج، وتوثيق كافة المسارات.

## 5. الخطوة التالية الدقيقة (Next Immediate Step)

البدء في تنفيذ **المرحلة 5**:
1. تثبيت Vercel AI SDK (`ai` و `@ai-sdk/openai`).
2. بناء معمارية الوكلاء الثلاثة (`qwen/qwen3.8-27b` و `openai/gpt-oss-120b`) عبر Groq endpoints مع منسق حتمي (`lib/ai/coordinator.ts`).
3. بناء API Route للتدفق: `app/api/chat/route.ts` مع دعم الـ streaming وعقد التنفيذ وفشل آمن وواضح عند غياب الاعتماد.
4. بناء أداة قراءة حقيقية (`lib/ai/tools/knowledge-lookup.ts`) بعقد Zod وحماية SSRF وحدود موارد وتوثيق النتيجة.
5. ربط واجهة مساحة الوكيل في `app/[locale]/agentnexos/page.tsx` مع API التدفق المباشر.
6. إجراء اختبارات تقييمية ذهبية (`scripts/test-agent-runtime.mjs`).
7. التحقق الكامل عبر `pnpm typecheck`, `pnpm i18n:check`, `pnpm test:rls`, `pnpm lint`, `pnpm build`.
