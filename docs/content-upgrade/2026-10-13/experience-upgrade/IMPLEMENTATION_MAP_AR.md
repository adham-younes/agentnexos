# خريطة النقل إلى التطبيق

| المصدر الحالي | النقل المطلوب | حدود التغيير |
|---|---|---|
| `app/[locale]/layout.tsx` | الاحتفاظ بمحمل الخطوط واتجاه الصفحة، وربط metadata لكل مسار | لا تبدل الخطوط اعتمادًا على اسم متغير قديم |
| `app/globals.css` | إضافة طبقة `.experience` أوCSS module وتحويل tokens المقترحة إلى نطاق واضح | لا تغير `--primary` عالميًا دون مراجعة أزرار الجذر والوكيل |
| `components/landing/cyber-home.tsx` | إدماج محتوى home كاملًا، hero الفني، بطاقات الحلول وروابطها | استبدل مصادر النص، واحتفظ بالتنقل ومحدد اللغة المنتجين |
| `components/cyber/effects.tsx` و`lightning.tsx` | تقليل المؤثرات المتكررة وفق reduced-motion، وفصل الرسم عن controls | لا تجمع lightning وvideo وcanvas في أول viewport |
| `components/cyber/console.tsx` | إبقاء المثال التوضيحي في صفحة الحل حيث يشرح المخرج | لا تصفه كتتبع تشغيل أو اعتمادات حقيقية |
| `components/agent/workspace.tsx` | إعادة ترتيب الواجهة بأجزاء Sidebar وButton وTable الموجودة؛ المحافظة على `useChat` والسياق والإلغاء والجاهزية والنسخ والتنزيل | لا تستبدلها بـWorkspace المرجعي غير المتصل |
| `lib/content/agent-workspace.ts` | نقل النصوص والبدايات الجديدة ومطابقة أكواد الخطأ | الميزانية منGET؛ لا تعتمد 1000 الثابتة لكل حالة |
| `lib/agents/prompts.ts` | مراجعة المرشح المرفق وتشغيل التقييمات قبل النقل | حافظ على المتابعات الضيقة والحدود الفعلية |
| `lib/agents/contract.ts` و`policy.ts` و`tools.ts` | استخدام العقد والأدوات القائمة كما هي، وأي تغيير له اختبارات مستقلة | لا تحول حالة human review إلى approval أو executable |
| `lib/agents/workflow.ts` و`app/api/agentnexos/route.ts` | استمرار source-of-truth للأحداث والأدلة والحدود | لا تبدل قواعد اتصال أو أسرار أو schema لحاجة زخرفية |
| الصفحات الجديدة تحت `app/[locale]` | قوالب Services/Solution/Sector/Guide/Legal من manifest | routes حقيقية في Next، لا hash router |
| `components/ui/*` | استخدام Button وSidebar وTable وTabs وغيرها كما ثبتت في المستودع | النسخ داخل النموذج لغرض استنساخ المعاينة فقط؛ لا تعِد نسخها إلى الإنتاج |
| `public/experience/` (مقترح) | ملفات webp وmp4 المحسنة مع أبعاد وحمولة معلومة | الصور الأربع البديلة في docs؛ الإنتاج يحمل صورة الاستخدام فقط |

## ما يؤخذ من النموذج

تركيب القصة، ترتيب النصوص، حالات الرسم، تخطيط المساعد، سلوك إعداد مثال ومراجعة موجز، وحدود الأصول. استخدم `TemporalLattice.tsx` كمرشح عميل مستقل دون API أو صلاحيات.

## ما لا ينقل كما هو

Hash routing، شريط فحص الصفحات، حالات المعالجة اليدوية، Google Fonts CSS الخارجي، placeholder labels التقنية لحالات الفحص، التبعيات وملف القفل الخاصان بالنموذج. هذه أدوات مراجعة وليست تجربة المستخدم النهائية. النسخة HTML تضم معظم الأصول للقراءة المحلية؛ النسخة الإنتاجية تستخدم ملفات static محددة وNext image sizing المناسب.

الدلالة الثابتة: اختيار مجال أو permission في الموجز يحدد احتياج المشروع، ولا يمنح النموذج سلطة. انتظار الاستجابة حالة طلب، لا نسبة إنجاز. لا يظهر سجل تشغيلي أو مصدر في UI إلا بإيصال فعلي محفوظ.

## مقارنة المضمون

لا تختصر فقرة الحزمة لكي تلائم التصميم. كل section يحتفظ بمعرفه والنص الكامل. تستخدم آلية render-comparison جميع42نسخة لكل صفحات الحزمة؛ الفقرة المخفية فيaccordion يجب أن تبقى في المصدر والعرض عند التوسيع. قارن النصوص بعد النقل إلى Next أيضًا، بما فيهاFAQ وsample outputs والتوجيهات ورسائل الفشل.

ملاحظتان تحريريتان ملزمتان: دقائق العمل تقبل الكسور والأرقام العربية والفارسية حسب السلوك الحالي. وعدد الحالات صحيح غير سالب. نص «حد التطبيق1000» يتحول إلى قيمةGET ديناميكية مع شرح «لكل اتصال خلال24ساعة»؛ لا تعرض سياسة ثابتة إذا تغيرت الإعدادات.
