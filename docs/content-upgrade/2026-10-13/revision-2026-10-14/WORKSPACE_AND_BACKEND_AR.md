# مساحة العميل ومنطق العمل والخادم

## فصل السياقات

المساعد العام /[locale]/agentnexos يقدم تصميمًا محدودًا. مساحة العميل المقترحة /[locale]/workspace تحتاج هوية وصلاحيات مثبتة من الخادم. لا تنقل تعليمات العميل إلى API العام، ولا تفتح صلاحيات العميل لمستخدم مجهول.

شاشات العميل: المهام، المعرفة والمصادر، الأدوات والاتصالات، الموافقات، المخرجات، سجل النشاط، وإعدادات المشروع. النصوص في workspace-copy.json. الواجهة تستهلك حالة من الخادم؛ لا تصنع بيانات حية من mock.

## عقد المهمة

معرف مهمة، مؤسسة ومشروع من جلسة خادم مثبتة، صاحب الطلب، الهدف، نطاق المصادر والأدوات، إصدار سياسة، مدخلات محققة، حالة، إصدار، ومرجع الأدلة. لا يأخذ الخادم organization_id أو capability من المتصفح كحقيقة.

draft → validated → queued → running → verifying → completed.
running قد ينتقل إلى awaiting_approval أو blocked_input أو blocked_permission أو failed أو cancellation_requested.
الموافقة الصحيحة تعيد المهمة إلى queued بمدخلات ثابتة؛ لا تعد المهمة completed بسبب اعتمادها.
cancellation_requested يصبح cancelled بعد نقطة توقف آمنة؛ لا تزعم الواجهة إلغاء أثر وقع خارجيًا.
فقد استجابة بعد طلب كتابة يصبح reconciliation_required، ثم يُفحص الأثر قبل retry.

## الأدوات

لكل أداة: اسم وفعل محدد، schema input/output، read/draft/write، مجالات وسجلات مسموحة، timeouts، ميزانية، وإثبات الأثر. الخدمات غير المتصلة تظهر «غير متصل»؛ الأدوات بلا صلاحية تظهر «لا تملك صلاحية الاستخدام».

الكتابة تحتاج اختبار idempotency أو مفتاح عمل يمكن المصالحة به. لا تعد تلقائيًا عندما لا يعرف النظام هل الإجراء نُفذ. لا ينفذ shell على خادم الموقع؛ تنفيذ الكود عند الحاجة يحتاج خدمة sandbox مستقلة وعزل ملفات وشبكة وموارد.

## الموافقات

approval_id، run_id، organization_id، approver_id، action، canonical_args_hash، payload_version، expires_at، policy_version، status. يعيد الخادم فحص الهوية والسياسة والصلاحية والحمولة عند الاعتماد وعند التنفيذ.

تغيير الحمولة يبطل الطلب القديم. موافقة مستخدم لا تعني صلاحية مستخدم آخر. لا يمنح النموذج أدوارًا ولا يختلق بديلًا لصاحب الاعتماد.

## المعرفة والذاكرة

كل أصل معرفة له مصدر وإصدار وحساسية ونطاق وصول وتاريخ تحديث. الاسترجاع يصفي المؤسسة والمشروع والمستخدم قبل النموذج. لكل سجل ذاكرة source/trust/scope/expiry وسبب حفظ، مع مراجعة مناسبة. أحداث المهمة تختلف عن ذاكرة المحادثة والسياسة.

التصحيح البشري ينشئ حالة تقييم؛ لا يغير policy تلقائيًا. اختبار منع خلط المستخدمين والمشاريع جزء من القبول.

## واجهة الخادم المقترحة

GET /api/workspace/capabilities: قدرات الجلسة الحالية وأدواتها.
POST /api/workspace/tasks: تحقق مدخلات وإنشاء مهمة؛ يدعم request_id لمنع الطلب المكرر.
GET /api/workspace/tasks/:id: حالة وخطوات ودليل بعد فحص الملكية.
POST /api/workspace/tasks/:id/cancel: طلب توقف؛ ليس نجاحًا فوريًا.
POST /api/workspace/approvals/:id/decision: قرار مع نسخة الحمولة وسياسة؛ تعارض الإصدار 409.
GET /api/workspace/artifacts/:id: وصول بعد فحص نطاق المؤسسة والمشروع.
هذه عقود تصميم؛ لا توجد هذه endpoints بوصفها API جديدة منشورة بهذه الدفعة.

## خطة قاعدة البيانات

افحص auth وربط الجداول والدوال الخاصة الحالية قبل تصميم إضافات. حافظ على جداول المحادثات الحالية وبياناتها. لا تعد بناء public أو تحذف migrations.

صمم في بيئة تطوير معتمدة نموذج مؤسسة/عضوية/مشروع/مهمة/خطوة/أداة/موافقة/مخرج/أثر وتقييم. RLS افتراضيًا مقيد؛ اختبر مستخدمين في مؤسستين، وجلسة انتهت، وعضوية سُحبت، ومخرجات مرتبطة بمهمة لا يملكها الطالب.

لا يُطبّق SQL من هذه الحزمة تلقائيًا؛ لا تحتوي migration إنتاجية متسرعة. عند اعتماد تغيير schema أنشئ migration بأداة المشروع، وفحصًا وتراجعًا، ثم نفذه في مرحلة مستقلة.

## حالات الواجهة

تحميل، فراغ، غير مصادق، غير متصل، نقص مدخلات، انتظار اعتماد، رفض سياسة، تشغيل، تحقق أثر، نجاح، فشل قابل للتعافي، فشل نهائي، إلغاء قيد التنفيذ، وإلغاء مكتمل. كل رسالة تصف حالة وصلتها من الخادم، لا نصًا يتوقعه النموذج.

تعرض الخطوات أحداثًا تشغيلية ومراجع أدلة؛ لا تعرض سلسلة التفكير الداخلية. تفصل المخرجات المقترحة عن artifact محفوظ، والإجراء المصرح عن الإجراء المنفذ.

## اختبارات الحدود

منع cross-tenant access في API/DB/retrieval؛ حقن مستند يطلب إرسال أسرار؛ تعديل approval payload؛ إعادة request_id؛ فشل بعد commit وقبل response؛ إلغاء متزامن؛ مصدر قديم؛ receipt غير موجود؛ انقطاع المزود؛ انقطاع التخزين. النجاح يحتاج أثرًا قابلًا للفحص في النظام النهائي.
