# Procurement: complete requests and decision-ready comparisons

Prepare the information purchasing needs before selecting a supplier. The proposed system gathers request details, flags gaps, organizes quotations and presents the file to the authorized reviewer.

## Where does the request stall?

A brief item description arrives without quantity or deadline, prompting another round of messages. Quotations may use different units, delivery terms or payment conditions, making price alone an unreliable comparison.

A starting scope might cover request review for one purchasing category. The organization defines required fields, comparison criteria and approval limits. The agent does not infer purchasing policy from generic examples.

## How a review case is prepared

- Capture the need, quantity, specifications, deadline and requester; request missing inputs before comparing.
- Retrieve permitted policies and quotations, recording dates and comparability.
- Apply approved rules to totals and supply terms, showing differences instead of inventing missing prices or bids.
- Route the file and notes to the owner. Supplier messages and purchase orders require separate connections and authorization.

## A lower quote is not an automatic selection

In an illustrative equipment request, one quote omits warranty duration while another includes warranty and delivery. The output shows differences and missing fields. The reviewer decides whether a quote is usable or needs clarification.

Missing approval policy, changes in value after approval, or conflicting specifications stop dependent steps. The file returns to its owner with a specific reason rather than being marked complete.

## What the team receives and tests

A consolidated file contains request details, a quotation matrix, gaps, exceptions and the review decision. Acceptance checks field completeness, calculations, traceability and approval levels.

A connected implementation needs request sources, approved policy, accessible quotations and a case-record system. Read access and file preparation can be the first scope. Integration and purchasing actions are specified and tested in the project.
