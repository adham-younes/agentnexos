# REDESIGN-03 — private conversations and account profile

## Implementation

Every model request requires verified, confirmed identity. A server-only transactional RPC validates conversation ownership and a unique request ID, then writes the user message before model execution. The server reconstructs bounded context from the account's stored messages, rather than accepting browser-supplied assistant history as evidence. Model output is written by the application server; client roles cannot forge assistant messages. Completion is shown only after the answer and execution metadata save successfully.

Conversations and messages use a composite owner foreign key, explicit grants and own-user RLS. Authenticated clients may read their own rows and delete their own conversations; cascading deletion removes messages. Clients cannot insert messages or invoke the server turn RPC. Storage is bounded to 200 conversations/account and 200 messages/conversation. Duplicate request identifiers are rejected. The UI lists conversations, supports confirmed deletion, account-name editing and a clear saved state. The privacy notice now describes stored text, model processing and separate quota metadata.

Migration `20261001083506_workspace_conversations.sql` applied to authorized project `ruereqpvykwnakcnmxha`. No enterprise connector or external execution capability was added. Database chat history is separate from durable execution, memory provenance and long-lived approvals.
