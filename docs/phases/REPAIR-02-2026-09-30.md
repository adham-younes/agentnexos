## Runtime rebuilding sequence

1. Trusted Supabase user session and verified organization membership; remove all body-supplied actor authority.
2. Durable run/step/approval repositories with RLS, tenant-denial tests against an actual database, expiry and replay-safe resumption.
3. Real provider requests with bounded budgets and recorded model usage. Separate static examples from provider output.
4. Real connector adapter with read-back verification. A locally generated receipt must never mean transmitted.
5. Approval binding to exact action parameters, authenticated decision owner, idempotency and reconciliation.
6. Scoped telemetry for authorized administrators, secret redaction and retention policy.
7. Live user journey before reopening runtime routes. No environment flag alone may reopen them.

Mastra is absent from current dependencies. Supabase migrations exist but their application and live isolation remain unverified. The landing security wording, remaining homepage claims and unused legacy dictionary entries still require a dedicated content pass. This repair is not completion of the enterprise runtime.
