# REDESIGN-04 — quality, account recovery and release handover

This source completes the planned review layer: password-recovery requests, authenticated password update, clear session-expiry links with a validated local return path, sign-out failures without false success, localized account metadata, conversation continuity when switching locale, and touch-sized language controls. Public pages stay public; no login or account page is indexed. SSR-only authentication cookies are HttpOnly, SameSite=Lax and Secure in production; no browser Supabase auth client requires token access.

Authentication configuration accepts only the authorized Supabase origin and a publishable or project-matching legacy anon key. Secret/service-role keys are rejected for SSR so a configuration mistake cannot bypass RLS. `/api/auth/status` returns safe configuration/provider-readiness codes, never credentials, user counts or account data. Provider reachability does not prove email delivery.

`pnpm verify:site` now targets the current design verifier rather than the archived photographic template contract. It checks route/link coverage, heading count, overflow, RTL/LTR, private-page redirects and anonymous agent denial. `pnpm verify:workspace` tests a temporary development-only component fixture with mocked network responses; it removes the fixture in finally. Run fixture verification before the production build, never concurrently. It does not establish real-account end-to-end behavior.

## Production gate

All source stages are prepared for review and staged Preview publication. Production is blocked by unconfigured or mismatched SSR public authentication configuration in Preview. Available Vercel tools cannot write environment variables and the attached cloud environment has no Vercel credential/outbound identity. This is not a paid-account requirement.

Before sequential production merges: complete public-key configuration; verify `/api/auth/status`; confirm signup email delivery and callback allowlist; test a controlled confirmed account, sign-in/out/recovery, saved-chat reload and own deletion, plus cross-account isolation. SQL and mocked UI evidence already exists but cannot substitute for these live account checks. No authentication, branch or billing protection is bypassed.
