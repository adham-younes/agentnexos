## 1. نطاق المرحلة وأهدافها

وفقاً للخطة الرئيسية (`docs/MASTER-PLAN-AND-HANDOFF-2026-09-29.md`) وقواعد `AGENTS.md`:
1. تأسيس طبقة التشغيل متعددة الوكلاء (Multi-Agent Runtime) باستخدام مكتبة `ai` (`ai@^7.0.118`) و`@ai-sdk/openai`.
2. ربط نماذج Groq المعتمدة:
   - نموذج التحليل والتنسيق الأساسي: `qwen/qwen3.8-27b`
   - نموذج التحقق والتدقيق المستقل: `openai/gpt-oss-120b`
3. تنفيذ منسق تشغيل منضبط وحتمي (`lib/ai/coordinator.ts`) يبني عقد تنفيذ ملزم (Execution Contract) لكل طلب، ويحدد حدود الأمان، ويطلب موافقة بشرية ملزمة عند العمليات الحساسة.
4. بناء أداة قراءة تشغيلية حقيقية (`lib/ai/tools/enterprise-lookup.ts`) مجهزة بمخطط Zod صارم (`enterpriseLookupInputSchema`) وتوليد بصمة إثبات تشفيرية (SHA-256 Digest).
5. توفير مسار API للتدفق المباشر (`app/api/chat/route.ts`) يعتمد Server-Sent Events (SSE) لضخ مراحل التشغيل والرموز الحية.
6. ترقية صفحة مساحة الوكيل (`app/[locale]/agentnexos/page.tsx`) لدعم التدفق المباشر وتحديث العقد الحي وتفعيل استعلامات تجريبية سريعة وبوابة الموافقة التفاعلية.
7. كتابة اختبار تقييم ذهبي آلي (`scripts/test-agent-runtime.mjs`) مسجل في `package.json` كـ `pnpm test:runtime`.

## 2. تفاصيل المعمارية والمكونات المنفذة

### 2.1 تعريف النماذج والبيئة (`lib/ai/models.ts`)
- قراءة مفاتيح Groq الحية على Vercel Production (`GROQ_API_KEY`, `GROQ_API_KEY1`, `GROQ_API_KEY2`).
- في حال غياب المفاتيح محلياً أو أثناء الاختبارات، الانتقال السلس التلقائي إلى مسار المعاينة الحتمية الشفاف دون استثناءات أو اختراع ردود وهمية.

### 2.2 أداة القراءة المؤسسية وبصمة الإثبات (`lib/ai/tools/enterprise-lookup.ts`)
- مخطط Zod صارم للتحقق من المدخلات:
  - طول الاستعلام من 1 إلى 300 حرف.
  - النطاقات المدعومة: `compliance`, `procurement`, `operations`, `general`.
- قاعدة معرفة تشغيلية واقعية لمنطقة الشرق الأوسط (متطلبات الفوترة الإلكترونية لهيئة الزكاة والضريبة والجمارك زاتكا المرحلة 2، ومصفوفة صلاحيات الشراء، وسياسات تشغيل الوكلاء وحماية SSRF).
- توليد بصمة إثبات تشفيرية SHA-256 hex من 64 خانة لكل استعلام ناجح.
- تصنيف النطاقات الحساسة تلقائياً لتتطلب موافقة بشرية (`requiresHumanApprovalForNextStep: true`).

### 2.3 منسق الوكلاء وعقد التنفيذ (`lib/ai/coordinator.ts`)
- استخراج القصد المؤسسي وتحديد نطاق العمل.
- صياغة عقد التنفيذ (`ExecutionContract`) المشتمل على:
  - الهدف المحدد للعملية
  - مصدر الحقيقة المعتمد
  - الأدوات المصرح بها فقط (أداة قراءة مقيدة)
  - حدود الأمان (حظر الإجراءات الحساسة دون موافقة)
  - متطلبات الدليل الرقمي (تسجيل بصمة SHA-256)
- إرجاع حالة `waiting_approval` عند العمليات الحساسة مع نص تصريح صريح.

### 2.4 التدفق المباشر عبر SSE (`app/api/chat/route.ts`)
- مسار HTTP POST يستقبل استعلام المستخدم ويعيد تدفق `text/event-stream`.
- بث الخطوة 1 (تحليل العملية وعقد التنفيذ).
- بث الخطوة 2 (تنفيذ أداة القراءة والنتائج).
- بث الخطوة 3 (تقييم بوابة الموافقة البشرية).
- بث رموز التوليف المباشر (Token streaming).
- بث حدث الإنجاز (`complete`) شاملاً بصمة الإثبات SHA-256 وزمن الاستجابة بالمللي ثانية ومحدد النموذج.

### 2.5 واجهة مساحة الوكيل التفاعلية (`app/[locale]/agentnexos/page.tsx`)
- دعم كامل للعربية (RTL) والإنجليزية (LTR).
- استهلاك تدفق SSE في المتصفح وتحديث العقد ومسار الخطوات حياً.
- أزرار استعلامات تجريبية مؤسسية سريعة.
- بوابة موافقة تفاعلية تسمح باعتماد الإجراء أو رفضه وإظهار بصمة التدقيق.
