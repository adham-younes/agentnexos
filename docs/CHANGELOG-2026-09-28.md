# سجل الفحص والتعديلات والاسترجاع

## 1. الفحص المنفذ قبل التطوير

- فحص الإنتاج العربي والإنجليزي على الديسكتوب والموبايل.
- فحص الأقسام الثلاثة عشر والروابط والأزرار والقائمة المتجاوبة.
- تشغيل Lighthouse على الإنتاج.
- مراجعة المستودع والتوثيق والمهارات والاعتماديات.
- مراجعة صحة المحتوى ومقارنة الادعاءات بالتنفيذ الفعلي.

### أبرز النتائج

- التطبيق كان صفحة تسويقية واحدة بلغتين، وليس منصة وكلاء مكتملة.
- Lighthouse المسجل قبل الإصلاح: 53 للموبايل و63 للديسكتوب، مع LCP يقارب 17.3 ثانية وحمولة تقارب 15.8MB.
- `pnpm lint` لم يكن يعمل لغياب ESLint.
- `next.config.mjs` كان يتجاهل أخطاء TypeScript ويفصل تحسين الصور.
- الاعتماديات أظهرت 31 تنبيهًا أمنيًا، منها 2 حرجة و16 عالية.
- روابط وأزرار عديدة كانت مؤقتة أو غير عاملة.
- تناقض دلالي بين العربية والإنجليزية، وادعاءات غير مدعومة عن التشغيل والبنية والتكاملات والأمان.
- التوثيق وخطة الطريق لم يطابقا حالة المستودع والإنتاج بصورة كاملة.
- المهارات مثبتة لـOpenHands وليست اكتشافًا تلقائيًا لـCodex، مع تداخل وتثبيت غير محكوم بمراجعات Git ثابتة.

التقرير الكامل محفوظ خارج المستودع ضمن مخرجات جلسة التدقيق، بينما يلخص هذا السجل الحقائق اللازمة لاستمرار المشروع.

## 2. محاولة المرحلة الأولى الملغاة

أُنشئ الالتزام `f0c4f4c` بعنوان:

`feat: launch Agentnexos phase one foundation`

احتوى على تحديث اعتماديات وبوابات جودة وواجهة ومحتوى جديدين ووكيل تجريبي ومخطط Supabase. نجحت الفحوص البرمجية ووصل النشر إلى الإنتاج.

لكن المحاولة **خالفت القيد البصري الأساسي**: استبدلت القالب وهوية الصفحة وصورها بدل تطوير المحتوى والوظائف داخل القالب نفسه. لذلك لا تُعتبر هذه المحاولة مرحلة منجزة، ولا يجوز البناء عليها بصريًا.

## 3. الإصلاح والاسترجاع

أُنشئ الالتزام `308c95a` بعنوان:

`Revert "feat: launch Agentnexos phase one foundation"`

ونُفذ الآتي:

- إلغاء كامل تغييرات الالتزام `f0c4f4c`.
- دفع الاسترجاع إلى `main`.
- انتظار نجاح فحص Vercel المرتبط بالالتزام.
- التحقق من أن الإنتاج عاد للمحتوى والقالب السابقين.

**رابط الإنتاج:** https://compute-the-platform-to-build-six-fawn.vercel.app/ar  
**التزام الاسترجاع:** `308c95a`  
**نتيجة نشر Vercel:** `success`

## 4. ما بقي صالحًا كمعرفة فقط

يمكن إعادة استخدام النتائج التالية في مراحل لاحقة، ولكن بإعادة تنفيذها فوق القالب الحالي:

- تحديث Next.js وإغلاق الثغرات المعروفة.
- إضافة ESLint وإزالة تجاهل أخطاء TypeScript.
- الانتقال من middleware إلى proxy عند تحديث Next.js.
- إضافة health وrobots وsitemap وترويسات الأمان.
- استخدام Vercel AI SDK و`ToolLoopAgent` للوكيل التجريبي.
- مخطط Supabase متعدد المؤسسات مع RLS وموافقات وسجل أحداث.
- البحث المرجعي عن منصات MENA.

هذه البنود **ليست موجودة حاليًا في الإنتاج** بعد الاسترجاع، ولا يجوز وصفها بأنها منفذة.

## 5. قرار منع تكرار الخطأ

من الآن فصاعدًا:

1. أي مرحلة تمس الواجهة تبدأ بصورة baseline من الإنتاج الحالي.
2. لا يُستبدل ملف الصفحة الرئيسية أو نظام التصميم كاملًا.
3. تعديلات المحتوى تُنفذ قسمًا واحدًا في كل دفعة، مع لقطة قبل وبعد.
4. لا دمج إلى `main` قبل عرض Preview ومراجعته.
5. إذا غيّر التنفيذ هوية القالب أو صوره أو نسبه، يُلغى قبل النشر.
6. التوثيق يميز دائمًا بين: مقترح، منفذ محليًا، منشور، ومتحقق إنتاجيًا.
