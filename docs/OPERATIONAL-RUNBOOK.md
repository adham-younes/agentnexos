# Agentnexos — Operational Runbook & Incident Management Guide

- **نسخة الوثيقة:** 1.0.0-Beta
- **تاريخ الاعتماد:** 2026-09-29
- **النظام:** منصة أنظمة الوكلاء المؤسسية Agentnexos (`compute-the-platform-to-build`)
- **الهدف:** توفير دليل تشغيلي دقيق وشامل لفرق العمليات لإدارة الحوادث، والتعافي من الأخطاء، وإجراءات التراجع الآمن (Safe Rollback).

---

## 1. تصنيف شدة الحوادث (Incident Severity Matrix)

| الشدة | الوصف والتأثير | زمن الاستجابة الأقصى (MTTA) | زمن المعالجة المستهدف (MTTR) | إجراءات التصعيد |
|---|---|---|---|---|
| **P0 (حرج / Critical)** | توقف كامل للمنصة، عطل في تدفق المحادثات `/api/chat`، أو خرق محتمل لحدود عزل المستأجرين أو RLS. | 15 دقيقة | أقل من ساعتين | استدعاء فوري لمهندس الحراسة (On-Call)، إخطار المالك، تفعيل خطة التراجع السريع (Rollback) عند الحاجة. |
| **P1 (رئيسي / Major)** | تعطل أحد النماذج المعتمدة في Groq، بطء شديد في الردود (> 10 ثوانٍ)، أو انقطاع موصل ZATCA مع استمرار باقي الخدمات. | 30 دقيقة | أقل من 4 ساعات | تفعيل المسار الحتمي التلقائي (Deterministic Fallback)، إخطار مسؤولي المؤسسات المتأثرة. |
| **P2 (متوسط / Moderate)** | تجاوز مؤسسة لحصتها الساعية (429 Throttled)، فشل غير متكرر في قراءة أداة معينة، أو خطأ في تصدير تقرير. | ساعتان | خلال يوم عمل | مراجعة سجلات التيليميتري `/api/telemetry`، زيادة حصة المؤسسة مؤقتاً إن لزم الأمر. |
| **P3 (طفيف / Minor)** | استفسار تشغيلي، خطأ نصي أو لغوي، أو تحسين في سجلات المراقبة. | 8 ساعات | خلال دورة التطوير القادمة | معالجة اعتيادية ضمن مهام الفريق. |

## 2. لوحات الفحص ونقاط المراقبة الصحية (Health & Diagnostics Endpoints)

تتيح المنصة نقاط نهاية برمجية مخصصة ومحمية لمراقبة الحالة التشغيلية لحظياً:

1. **فحص الصحة الشامل (System Health):**
   ```bash
   curl -s https://compute-the-platform-to-build-six-fawn.vercel.app/api/health | jq .
   ```
   - يتحقق من: وقت التشغيل (Uptime)، جاهزية الـ Runtime والنماذج، اتصال Supabase، تفعيل درع الأمان، وحالة الذاكرة وسجل التدقيق المشفر.

2. **فحص سجل التيليميتري والارتباط (Telemetry & Tracing):**
   ```bash
   curl -s "https://compute-the-platform-to-build-six-fawn.vercel.app/api/telemetry?limit=20" | jq .
   ```
   - يتيح تتبع الأخطاء حسب `correlationId`، ومراقبة أزمنة الاستجابة، وتصنيف الأخطاء الآلية.

3. **فحص صحة الموصلات المؤسسية (Enterprise Connectors Health):**
   ```bash
   curl -s "https://compute-the-platform-to-build-six-fawn.vercel.app/api/connectors?organizationId=org_pilot_acme" | jq .
   ```
   - يتحقق من استجابة موصل فاتورة ZATCA، موصل ERP، ومستودع البيانات المحوكم.

## 3. كتيبات معالجة الحوادث الشائعة (Incident Playbooks)

### 3.1 سيناريو: تجاوز حدود التدفق وحصص الاستخدام (Rate Limiting / 429)
- **الأعراض:** استلام المستخدم لرمز الاستجابة `429 Too Many Requests`.
- **السبب:** تجاوز المؤسسة لـ 5 طلبات في النافذة المنزلقة أو استنزاف ميزانية التوكنات الساعية (200,000 توكن).
- **الإجراء:**
  1. التحقق من ترويسة `Retry-After` المرجعة وتمريرها للمستخدم.
  2. في حال كان الطلب عاجلاً لمؤسسة تجريبية ذات أولوية، يتم تحديث حصة المؤسسة عبر `lib/enterprise/quotas.ts`.

### 3.2 سيناريو: تعطل أو بطء نموذج Groq الخارجي
- **الأعراض:** تأخر في استجابة النماذج السحابية أو انقطاع خدمة Groq.
- **الإجراء الآلي:** تم تصميم المنسق `coordinator.ts` ليعمل بنظام الحماية الحتمية التلقائية (`isDeterministicFallback = true`) حيث يتم توليد عقود التنفيذ وتشغيل الأدوات الحقيقية وإصدار بصمات SHA-256 دون أي توقف لعمل العميل.

### 3.3 سيناريو: رصد محاولة اختراق أو تجاوز للأوامر (Prompt Injection Attack)
- **الأعراض:** ظهور حالة حظر `guardStatus: blocked` في سجلات التيليميتري.
- **الإجراء:**
  1. يتم الحظر الفوري عند الخطوة صفر (Step 0) خلال أقل من 1ms عبر درع الأمان `prompt-guard.ts`.
  2. يتم تسجيل حدث انتهاك أمني `security_violation` في سجل التدقيق المشفر غير القابل للتلاعب.
  3. لا يتم إرسال أي استفسار إلى النماذج أو الأدوات، مما يحمي النظام من أي استنزاف أو تسريب.

## 4. خطة التراجع السريع والآمن (Safe Rollback Plan)

في حال حدوث خطأ حرج (P0) غير قابل للإصلاح الفوري أثناء نشر إصدار جديد:

### الخطوة 1: الفحص الفوري والتأكد من الإصدار الحالي
```bash
git log -n 3 --oneline
```

### الخطوة 2: تشغيل سكربت التراجع الآلي
تم إعداد سكربت تشغيلي مؤتمت في المستودع:
```bash
bash scripts/rollback-plan.sh
```

### الخطوة 3: التراجع اليدوي عبر Git وVercel (في حال الطوارئ)
1. إعادة تعيين الفرع `main` للـ commit السابق المستقر:
   ```bash
   git checkout main
   git revert --no-edit HEAD
   git push origin main
   ```
2. أو من خلال لوحة تحكم Vercel:
   - الانتقال إلى مشروع `compute-the-platform-to-build`.
   - اختيار النشر السابق المستقر (Instant Rollback) والضغط على **Promote to Production**.
3. التحقق الفوري من استعادة الخدمة عبر فحص نقطة النهاية:
   ```bash
   curl -f -s https://compute-the-platform-to-build-six-fawn.vercel.app/api/health
   ```
